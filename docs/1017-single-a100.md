# Testing DeepSeek-V4.1-Flash-1017 on one A100

This is an experimental compatibility/test recipe, **not a reproduced 58.9 tok/s
benchmark**. Full-model inference and A100 performance still need measurement on
real hardware. The launcher does not download or modify weights.

## one-server review (2026-10-20)

The [readiness assessment](1017-one-server-readiness.json) records official
checkpoint revision `1bae0e1088993b9b82de08f59de5be5a34e42170` and the actual host.

| Resource | Observed | Needed by this runtime |
| --- | --- | --- |
| GPU | One A100-SXM4 80GB | Expert offload; guard requires 70,000 MiB free and no compute processes |
| Host RAM | About 236 GiB | 457.778 GiB resident expert/Engram copies; preflight requires 465.778 GiB including 8 GiB headroom |
| Disk | About 120 GiB free on `/data` | 475.251 GiB for 48 safetensors files plus metadata/runtime space |
| CPU | EPYC 7H12, 16 vCPUs, AVX2/FMA | New AVX2 fallback; previous Sapphire Rapids code used unsupported instructions |
| Checkpoint | Absent at configured path | Complete original HF layout |

VRAM waiting cannot resolve insufficient RAM capacity or disk space. Both CPU
computation and GPU-streaming expert offload keep the packed experts in host RAM;
Engram is also copied into RAM. The loader does not stream weights from disk.
No full checkpoint was downloaded and no unrelated jobs or data were removed.
The 8 GiB headroom is a lower-bound startup check, not a peak RSS guarantee.
Provision additional memory for the OS, serving caches and other workloads.

CPU MoE now compiles for the current CPU with an ISA-specific cache and atomic
installation, honors process affinity and actual NUMA node IDs, and preserves
reserved main-thread CPUs. Noncontiguous expert loading keeps temporary buffers
alive; empty routing clears its output. Small native tests cover BF16 and existing
W4A8 modes; they do not establish full-model quality or TPS.

Final focused validation: **114 passed, 14 CUDA skipped** both locally with CPU
PyTorch and on one-server with `CUDA_VISIBLE_DEVICES=''`. All **9 CUDA sources**
compiled for `sm_80` using the server's existing CUDA 13 toolkit. The remote check
exited **0**; its log/exit paths and versions are recorded in the readiness JSON.
Compilation does not verify GPU execution. The 14 real-CUDA cases are queued
separately behind the existing shared lock; full-model inference remains blocked.

### Background pipeline

Run from the repository root in an existing runtime environment:

```bash
umask 077
mkdir -p "$HOME/logs"
chmod 700 "$HOME/logs"
export DSV41_JOB_DIR
DSV41_JOB_DIR=$(mktemp -d "$HOME/logs/deepseek1017.XXXXXXXX")
export DSV41_PYTHON=/path/to/runtime/bin/python
export DSV41_NVCC=/path/to/cuda/bin/nvcc
export DSV41_1017_CKPT=/data/one/models/DeepSeek-V4.1-Flash-1017
export DSV41_GPU=0
export DSV41_MIN_FREE_MIB=70000
# Use the exact existing fleet flock; do not bypass or remove another job's lock.
export DSV41_GPU_LOCK_FILE=/home/one/.cache/infusion/gpu-GPU-9e8642f5-f480-63be-da66-b6134587199a.lock
nohup bash ./run_1017_one_server.sh > "$DSV41_JOB_DIR/job.log" 2>&1 < /dev/null &
echo "$!" > "$DSV41_JOB_DIR/job.pid"
printf '%s\n' "$DSV41_JOB_DIR"
```

The script first records prerequisites in `resources.json`, then queues synthetic
CUDA tests in `gpu-tests.json`. After those pass, `model.json` tracks the resource
wait, GPU wait and 128-token smoke benchmark. Successful benchmarking is followed
by the localhost API on port 8107. Timing/token counts are printed to `job.log`.
`job.exit` appears only after the pipeline, including the server, has exited.
Each JSON records its supervisor PID and state; the shell PID is in `job.pid`.

`one_server` rechecks missing checkpoints/host RAM every 300 seconds without
importing torch or holding a GPU lock. Once ready it execs `wait_gpu`, which
acquires flock and checks free VRAM and compute processes on three polls 30
seconds apart. The child sees only the selected GPU UUID as logical device 0.
The lock is held for its lifetime. Signals are forwarded and JSON updates are
atomic. GPU tests failing stops the pipeline. External programs that ignore flock
can still race the checks; the guard does not reserve VRAM against those jobs.

```bash
cat "$DSV41_JOB_DIR/resources.json"
cat "$DSV41_JOB_DIR/gpu-tests.json"
test ! -f "$DSV41_JOB_DIR/model.json" || cat "$DSV41_JOB_DIR/model.json"
test ! -f "$DSV41_JOB_DIR/job.exit" || cat "$DSV41_JOB_DIR/job.exit"
tail -n 40 "$DSV41_JOB_DIR/job.log"
```

## Numerical change

The official [1017 reference model](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/main/inference/model.py)
quantizes and dequantizes the attention output after inverse RoPE and before the
block-diagonal `wo_a` projection, in **both `Attention` and `DSparkAttention`**:
per-32 activations, E4M3 rounding, power-of-two scales, then back to BF16.
The custom runtime's shared `w8.oproj_a` was missing this operation.

`DSV41_O_FP8_QDQ=1` adds it before all BF16, packed-W8, chunked, and fallback
projection paths. CUDA uses the existing Ampere-compatible fused Triton kernel;
small CPU tests use the existing torch reference. The input is not modified.

The flag is read at import, before graph capture. Restart the process to change
it. An unset flag (or `0`) preserves this repository's **old runtime behavior**;
it is not a claim that disabling QDQ matches today's older-model reference.
The currently published older Flash reference also contains this operation.

The `run_1017` launcher sets the flag in a fresh interpreter, passes an explicit
checkpoint to avoid the upstream legacy/Abliterated default, and selects a
separate prefix-cache epoch so old cached hidden states are not reused.
Changing other numerical settings still requires fresh caches/processes.
The launcher also fixes `DSV41_W8=1`, `DSV41_MAX_SEQS=1` and the 1017 model name.
Persistent prefix caching defaults off to avoid scanning, evicting or writing an
existing shared tmpfs cache. To opt in, use a dedicated `--prefix-cache-dir`.

## Environment and checkpoint

Use an existing working Linux A100 runtime environment with PyTorch, Triton,
NumPy, transformers, Pillow, and the CUDA toolkit (`nvcc`; upstream expects 12.8).
CPU offload also needs `g++` and an x86 CPU with AVX2/FMA. AVX512/BF16/VNNI-capable
hosts retain the optimized native path; the EPYC host uses the AVX2 fallback.
A100 80GB plus substantial host RAM is the intended test
configuration; it is not a validated minimum-memory guarantee.

Download the **original HF safetensors** checkpoint including `inference/` and
`encoding/`, not GGUF or the reference runtime's converted per-rank checkpoint:

```bash
export CKPT="$HOME/models/DeepSeek-V4.1-Flash-1017"
hf download deepseek-ai/DeepSeek-V4.1-Flash-1017 --local-dir "$CKPT"
# Set this when nvcc is not on PATH:
export DSV41_NVCC=/usr/local/cuda-12.8/bin/nvcc
export CUDA_VISIBLE_DEVICES=0
```

Run from the repository root in the activated runtime environment. The selected
physical GPU appears as logical device `0`; all launcher modes pass `--devices 0`.
Preflight checks the original config, safetensors headers/data extents and index
membership, effective host RAM (including cgroup-v2 limits), and compilers without
reading tensor data. This does not authenticate model identity or weight hashes,
or guarantee GPU/CPU kernel correctness or sufficient peak RAM/VRAM.

```bash
# No torch import or CUDA allocation; nonzero exit explains missing prerequisites.
python -m dsv41.run_1017 bench --ckpt "$CKPT" --preflight
```

## Smoke test, calibration, and benchmark

```bash
# No torch import, model loading, or checkpoint access:
python -m dsv41.run_1017 bench --ckpt "$CKPT" --dry-run

# Short correctness smoke test: all experts in CPU RAM, no hot cache yet.
python -m dsv41.run_1017 bench --ckpt "$CKPT" --max-new-tokens 128

# Calibration must use eager decode: upstream graph decode does NOT record
# ROUTE_STATS. The launcher selects eager automatically for --route-stats.
python -m dsv41.run_1017 bench --ckpt "$CKPT" \
  --hot-experts 0 --max-new-tokens 512 \
  --prompt "Explain dynamic programming with several examples." \
  --route-stats results/route_stats_1017.pt

# Optimized graph decode using the newly collected 1017 routing profile:
python -m dsv41.run_1017 bench --ckpt "$CKPT" \
  --hot-experts 16 --hot-stats results/route_stats_1017.pt \
  --max-new-tokens 512 --prompt "Write a Python LRU cache with tests."
```

Calibration is not a throughput result. Its output file is overwritten on each
run. A single prompt is only a smoke-test profile, not representative calibration:
measure on held-out Korean, English, and coding prompts. Compare hot-expert counts
8/16/24/32 subject to available VRAM. Do not silently reuse upstream `route_stats.pt`.
An explicit hot-stats file is required when enabling the hot cache.

The benchmark uses greedy sampling (`temperature=0`) for repeatability and prints
upstream's separate prefill/decode timings and actual generated token count. EOS
may end generation before `--max-new-tokens`. Repeat after warm-up and record CPU,
RAM, PCIe/SXM, runtime versions, context length, and cache configuration. For
bottleneck diagnosis use `--profile` separately; profiling changes timing.

## Chat and API

```bash
python -m dsv41.run_1017 chat --ckpt "$CKPT" \
  --hot-experts 16 --hot-stats results/route_stats_1017.pt

python -m dsv41.run_1017 serve --ckpt "$CKPT" \
  --hot-experts 16 --hot-stats results/route_stats_1017.pt
```

Chat defaults to temperature/top-p 1.0. The API binds to `127.0.0.1:8000`, uses
one sequence and no MTP, and defaults to a 512-token response cap (configurable
with `--max-new-tokens`). Set sampling parameters in API requests. The upstream
API model aliases are unchanged; the checkpoint passed above selects the weights.
Use non-streaming requests for the first API test; the upstream SSE lifecycle
issue is outside this PR. This PR does not certify full-model MTP correctness or
speed, even though the shared projection fix also covers its call sites.

Direct use of `dsv41.run`, `dsv41.chat`, or `dsv41.serve` still requires explicitly
exporting `DSV41_O_FP8_QDQ=1`, choosing a fresh `DSV41_PREFIX_CACHE_EPOCH`, and passing
`--ckpt`. Merely pointing an old launcher at 1017 does not activate this opt-in fix.

## Tests

```bash
python -m pytest -q tests/test_1017_compat.py tests/test_1017_launcher.py
# On the A100 host: real Triton/CUDA projection and CUDA Graph replay tests.
python -m pytest -q tests/test_1017_cuda.py
python -m pytest -q tests/test_cpumoe_portability.py tests/test_wait_gpu.py tests/test_one_server.py
```

CPU tests cover numerical rounding, zero/small/large values, non-contiguous inputs,
legacy opt-out, BF16 and mocked-W8 dispatch/fallback, configuration, checkpoint
preflight, and launcher isolation. The optional GPU tests exercise real kernels
and skip when CUDA is unavailable. Neither suite loads the full model. Validate
logits/generated outputs against the official 1017 reference before relying on
application quality, and measure decode tps separately; no tps result is claimed.
